## v0.2.1 印尼失败场景修复

- 用户原报告已生成，但五项实质答案均为未知：仅取得法规介绍页，正文 PDF 未读取。已复现嵌入 PDF 漏检、2 MB 上限、PDF 不支持、慢下载串行阻塞及研究超时后材料丢失。
- 增加 pypdf 依赖、嵌入 PDF 发现、20 MB 上限、按页读取与关键词定位；下载使用有强 ETag 校验的 HTTP Range，单文件总预算 100 秒，MCP 工具最多 3 项并行。扫描件无文字时不宣称已完成 OCR。
- 真实读取验证：PP 35/2021 共 56 页，已提取并检查固定期限、续签、试用及通知条款所在页；UU 6/2023 劳动部分取得第 1—24 页；UU 13/2003 取得第 21 页。来源与页码来自实际工具记录。
- 完整研究曾达到时间上限。恢复整理使用上述真实中断轨迹，并补充一次真实 Codex 读取 UU 13/2003 第 21 页；没有重新重复整轮检索。无工具整理阶段约 137 秒完成，生成三份 PDF 来源支持的五主题报告。
- 新报告不再全部未知，但明确 research_incomplete=true：最新判例影响、部分条文现行效力及具体解除事由仍未定版。这是恢复路径的真实验证，不声称新版本从零开始的印尼全量研究已稳定完成。
- 单次总预算为 600 秒：研究最多 300 秒，必要时再用最多 300 秒整理已完成工具返回的正文；两个阶段共享剩余总预算。整理阶段禁用工具，不允许模型记忆补规则。
- 207 项离线测试通过，含 PDF、分段下载、并发、来源页码、超时恢复、材料截断降级与无效编码拒绝；独立评审的问题均有回归测试。

## 复现

```bash
python -m unittest discover -s tests -v
node --check employment_agent/static/app.js
python -m employment_agent
```

网页打开 `http://127.0.0.1:8765`，可选择“查看演示”，或默认使用本机 Codex。安装 Codex 并由本人完成登录后，网页复用其已有认证；只有切换“OpenAI API”模式才需要网页密钥或 OPENAI_API_KEY。

## API 实现依据

- [OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)
- [OpenAI Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- [Codex Authentication](https://developers.openai.com/codex/auth)
- [Codex Non-interactive mode](https://developers.openai.com/codex/noninteractive)

API 模式采用 Responses API；本机模式采用 Codex exec 与本项目只读 MCP。接口可用性仍受账户权限、模型能力、网络与服务更新影响。
